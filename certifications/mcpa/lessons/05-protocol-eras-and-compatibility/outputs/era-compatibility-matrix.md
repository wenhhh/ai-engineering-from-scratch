# 协议时代兼容性矩阵（Protocol Era Compatibility Matrix）

面向 MCPA“MCP 基础”领域的一页参考，对齐 MCP 2026-07-28。

## 版本时间线

| 版本 | 时代 | 主要变化 |
|---|---|---|
| 2024-11-05 | 旧版（Legacy） | 首个公开版本：stdio 与 HTTP+SSE 传输，以及每次建立连接时的旧式握手。 |
| 2025-03-26 | 旧版（Legacy） | Streamable HTTP 替代 HTTP+SSE；引入 OAuth 2.1 授权、工具注解与音频内容。 |
| 2025-06-18 | 旧版（Legacy） | 结构化工具输出、资源链接、信息征询、OAuth 资源服务器分类、MCP-Protocol-Version 请求头；移除 JSON-RPC 批处理。 |
| 2025-11-25 | 旧版（Legacy） | 图标、增量权限范围同意、工具命名指引、URL 模式信息征询、实验性任务；校验错误成为工具执行错误。 |
| 2026-07-28 | 现代（Modern） | 无状态核心，移除握手和会话；增加 server/discover、多轮往返请求、resultType 和 subscriptions/listen；任务移入扩展；弃用 roots、sampling、logging 和动态客户端注册。 |

## 术语

- **现代（Modern）**：2026-07-28 及后续版本。版本、身份与能力通过每请求元数据传递。
- **旧版（Legacy）**：2025-11-25 及更早版本。连接以创建会话的握手开始。
- **双时代（Dual-era）**：同时支持两者的实现，在解析前明确判定时代。

## stdio 探测

发送其他请求前，先发送 `server/discover`，在 `_meta` 中携带客户端首选版本：

1. 返回 `DiscoverResult`：服务器属于现代时代。从 `supportedVersions` 中选择版本。
2. 返回可识别的现代错误（例如 `UnsupportedProtocolVersionError`，代码 -32022）：服务器属于现代时代，但需要其他版本。从 `data.supported` 中选择版本重试，不回退。
3. 其他错误，或在合理超时内没有回答：按旧版服务器处理，回退到旧版握手。

不能把回退绑定到某个特定错误码：无法识别的错误和超时具有相同的时代判断结果。

## HTTP 探测

先尝试现代请求。收到 `400 Bad Request` 时，先读正文再判断：

- 正文中有可识别的现代 JSON-RPC 错误：仍为现代服务器。重试或修正请求，不回退。
- 正文为空，或不是可识别的现代错误：按旧版处理。回退到旧版握手，还可能继续回退到已弃用的 HTTP+SSE 传输。

## 兼容性矩阵

| 客户端 | 服务器 | 结果 |
|---|---|---|
| 现代 | 现代 | 可用。server/discover 可选；版本不匹配表现为 UnsupportedProtocolVersionError，客户端使用双方共同支持的版本重试。 |
| 现代 | 旧版 | 失败。旧版服务器不按每请求元数据处理；双时代探测本可在重要请求之前发现这一差异。 |
| 双时代 | 现代 | 可用。探测返回 DiscoverResult 或可识别的现代错误，客户端继续使用现代路径。 |
| 双时代 | 旧版 | 可用。探测返回无法识别的错误或超时，客户端回退到旧版握手。 |
| 旧版 | 现代 | 失败。旧版客户端的开场请求调用了现代服务器未实现的方法，也缺少现代服务器必需的元数据。 |
| 旧版 | 双时代 | 可用。服务器回答旧版握手，并按协商出的旧版本服务该客户端。 |
| 旧版 | 旧版 | 可用，完全遵守对应旧版本自身的规则。 |

## 考试要点

- 2026-07-28 没有握手和会话，每个请求都能自描述。
- 时代判断描述服务器，按进程（stdio）或源站（HTTP）缓存；后来失效时可以重新探测。
- 现代专用服务器在拒绝旧版连接尝试时，仍应在错误中列出支持版本，因为仅支持旧版的客户端没有其他办法得知可用版本。
- 可识别的现代错误从不触发旧版回退；只有无法识别的错误或超时才触发。
