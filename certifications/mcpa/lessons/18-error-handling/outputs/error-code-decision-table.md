# 错误码决策表（Error Code Decision Table）

MCP 2026-07-28 请求失败时，用于选择通道、编号、数据结构和 HTTP 状态的一页参考。完整讲解见 `docs/en.md`。来源：`certifications/mcpa/research/mcp-2026-07-28-brief.md`，第 5 节。

## 第 1 步：选择通道

| 失败涉及 | 通道 | 结构 |
|---|---|---|
| 请求本身：未知方法、未知工具、无效封套或服务器故障 | 协议错误 | `{"jsonrpc": "2.0", "id": ..., "error": {"code": ..., "message": ..., "data": ...}}` |
| 工具参数检查或执行中发现的问题：无效输入、API 失败、业务规则、过期句柄 | 工具执行错误 | 正常 `complete` 结果：`{"content": [...], "isError": true}` |

对于模型可修正的工具输入或业务问题，优先考虑工具执行通道。未知工具、无效请求和服务器内部故障等才属于协议错误；模型不能像处理 `isError` 内容那样，简单靠调整工具参数修复协议层问题。

## 第 2 步：选择编号，仅用于协议错误

| 编号 | 名称 | 触发条件 | HTTP 状态 |
|---|---|---|---|
| -32700 | 解析错误（Parse error） | 正文不是合法 JSON，无法读取 `id`，因此返回 `null` | 规范未指定，通常为 400 |
| -32600 | 无效请求（Invalid Request） | JSON 合法，但不是有效的 JSON-RPC 2.0 对象 | 规范未指定 |
| -32601 | 找不到方法（Method not found） | 服务器不实现请求指定的方法 | 404 |
| -32602 | 参数无效（Invalid params） | 未知工具、缺少必需 `_meta`、资源缺失、无效提示词名称或参数、无效游标、无效日志级别 | 400 |
| -32603 | 内部错误（Internal error） | 服务器自身故障 | 规范未指定 |
| -32020 | HeaderMismatch | HTTP 头部与正文不一致，或缺少必需请求头 | 400 |
| -32021 | MissingRequiredClientCapability | 需要当前请求 `clientCapabilities` 未声明的能力，携带 `data.requiredCapabilities` | 400 |
| -32022 | UnsupportedProtocolVersion | 不支持指定协议版本，携带 `data.supported` 和 `data.requested` | 400 |

## 第 3 步：不发送这些编号

| 编号 | 禁用原因 |
|---|---|
| -32000 至 -32019 | 2026-07-28 分配政策之前的旧版子区间，新实现不得在此分配或使用编号。 |
| -32002 | 截至 2025-11-25 曾用于资源未找到，SEP-2164 改为 -32602。 |
| -32042 | 仅在 2025-11-25 中用于要求 URL 信息征询，没有替代编号，改用信息征询流程。 |
| -32020 至 -32099 中的其他编号 | 保留给 MCP 规范，只有 -32020、-32021、-32022 已定义，不能使用其他未定义编号。 |

在发送到网络之前就应拒绝构造这些错误码。将防护放入组装错误响应的公共函数，如 `code/main.py` 中的 `safe_error`，避免禁用编号离开进程后才被发现。

## 第 4 步：正确放置应用自定义编号

现有 MCP 编号和 `isError` 都不适用时，新编号应完全位于 `-32768` 至 `-32000` 之外，例如双方另行约定的小正整数。仍应先考虑 `isError`；SEP-1303 的目的就是减少对本可由模型读取并修正的问题随意发明错误码。

## 没有 JSON-RPC 编号的传输事件

| 事件 | HTTP 状态 | 是否携带 JSON-RPC 错误？ |
|---|---|---|
| 接受通知 POST | 202 Accepted | 否，完全没有正文 |
| 对 MCP 端点发送 GET 或 DELETE | 405 Method Not Allowed | 否 |
| bearer 令牌缺失或无效 | 401 Unauthorized | 否，属于 OAuth 层响应 |
| 权限范围不足 | 403 Forbidden | 否，属于 OAuth 层响应 |

## 回传请求 id 规则的唯一例外

无法读出请求标识时，例如原始正文解析失败，无法回传原始 id。原文将此概括为省略 `id`；译注：本课正文和可运行测试使用的是 id: null，应按该明确形式理解，不能将其误写为缺少字段。其他结果或错误响应均回传原请求的相同 id。
