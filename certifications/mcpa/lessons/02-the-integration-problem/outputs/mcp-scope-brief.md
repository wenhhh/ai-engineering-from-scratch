# MCP 范围简报（MCP Scope Brief）

面向 MCPA 的“MCP 基础”领域、对齐 MCP 2026-07-28 的单页参考。

## 核心论证

没有共享协议时，N 个 AI 应用与 M 个系统需要 N 乘 M 套定制集成。采用 MCP 后，每个应用实现一次客户端，每个系统实现一次服务器，共 N 加 M 份实现。四个应用与六个系统从 24 套集成降为 10 份实现；每个新系统只增加一份实现，不必增加四套。

## MCP 标准化的部分

- 服务器如何描述自己：`server/discover` 返回受支持版本、能力与身份。
- 客户端如何获知服务器提供什么：`tools/list`、`resources/list`、`prompts/list`。
- 如何调用工具、返回结果和错误：`tools/call`、`CallToolResult`、JSON-RPC 错误。
- 每个请求通过 `params._meta` 携带的元数据：协议版本和客户端能力为必需，客户端身份为建议。

## MCP 留给应用决定的部分

宿主使用哪个模型、如何构建提示词、如何呈现对话，以及何时请求用户批准。

## 参与方与原语

| 组成 | 一句话说明 | 控制方 |
|------|--------------|---------------|
| 宿主（Host） | 用户使用的应用 | 用户 |
| 客户端（Client） | 代表宿主与一个服务器通信 | 宿主 |
| 服务器（Server） | 提供工具、资源和提示词 | 其运营方 |
| 工具（Tool） | 带名称、说明和输入模式的操作 | 模型 |
| 资源（Resource） | 通过 URI 标识的可读数据 | 应用 |
| 提示词（Prompt） | 可复用模板 | 用户 |

## 两个错误通道

| 情形 | 通道 | 示例 |
|-----------|---------|---------|
| 请求本身错误 | JSON-RPC 错误 | 未知工具：`-32602` |
| 工具遇到模型可以修正的问题 | 带 `isError: true` 的结果 | 缺少参数或参数无效 |
| 请求使用服务器不支持的版本 | JSON-RPC 错误 | `-32022`，附带 `data.supported` |

## 考试要点

- 2026-07-28 没有 `initialize` 握手，也没有会话。
- 每个结果都携带 `resultType`。
- 未知工具使用 `-32602`；`-32601` 用于未知方法。
