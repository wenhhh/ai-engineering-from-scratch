# 信任边界图谱（Trust Boundary Map）

面向 MCPA“安全与治理”领域的一页参考，对齐 MCP 2026-07-28。

## 五个区域

| 区域 | 定义 | 默认信任 |
|------|------------|----------------|
| 用户与宿主 | 使用者及其运行的应用 | 信任根，其他区域的信任来自这里作出的选择 |
| 客户端 | 宿主内负责与某台服务器通信的组件 | 可信，由宿主拥有并嵌入 |
| 服务器 | 本地或远程的独立程序，常由第三方提供 | 默认不可信，本地 stdio 管道也不例外 |
| 上游系统 | 服务器进一步调用的系统 | 不可信，通常完全无法被客户端观察 |
| 模型 | 阅读组装后上下文的语言模型 | 位于所有区域下游；服务器来源内容应按数据处理，不能自动赋予指令权限 |

## 进入模型的不可信内容

- 工具的 `name`、`description`、`icons` 和 `annotations`
- `tools/call` 结果的 `content` 块与 `structuredContent`
- `resources/read` 返回的文本与二进制内容
- `server/discover` 中的 `instructions` 文本
- 上述内容中嵌入的任何信息，包括看起来像指令的文字

## 应用规则

- **自报身份**：`clientInfo` 和 `serverInfo` 仅用于展示、日志和调试。信任决策根据宿主记录的实际连接目标，不根据对端自称的名称。
- **不可信注解**：声明服务器不在宿主信任列表时，`readOnlyHint`、`destructiveHint`、`idempotentHint` 和 `openWorldHint` 都不可信。安全判断回退到保守默认值，依次为 false、true、false、true。
- **图标安全**：只接受 `https:` 和 `data:` 图标 URI，拒绝 `javascript:`、`file:`、`ftp:` 及其他方案。获取时不发送凭据，SVG 按潜在可执行内容处理。
- **多服务器隔离**：一台服务器内容中的指令，不能独立构成调用另一台服务器工具的理由。跨边界调用须源于模型基于用户请求的自主选择，有副作用时仍经过同意门禁。
- **本地服务器同意（SEP-1024）**：一键安装本地服务器前，客户端必须展示未经缩略的完整命令，并获得用户明确批准。
- **DNS 重绑定**：本地 HTTP 服务器检查 `Origin`，拒绝不认可的来源，不能仅因请求到达 `127.0.0.1` 就信任它。
- **stdio 凭据**：从环境读取凭据，不在 stdio 传输上运行 OAuth 授权流程。

## 风险信号检查清单

- 工具结果包含点名另一台服务器或另一工具的指令
- 图标 URI 使用 `https` 或 `data` 之外的方案
- 不在允许列表中的服务器声称 `destructiveHint: false`，客户端却直接采信
- 本地启动命令来自返回内容，而非宿主自己的配置
- 本地 HTTP 服务器不检查 `Origin` 就接受请求
- 任一授权或信任决策使用了 `serverInfo.name`

## 考试要点

- `clientInfo` 和 `serverInfo` 只供展示等用途，不能充当安全决策依据。
- 工具注解始终属于提示，不能直接等同于行为保证。
- 本地服务器被攻陷的安装场景，应追溯 SEP-1024 的同意要求。
- 跨服务器嵌入指令应由宿主拒绝；承载它的线上消息可能完全合法，不能靠 JSON-RPC 错误来表达内容风险。
