# 架构角色图谱（Architecture Roles Map）

面向 MCPA“架构与组件”领域的一页参考，对齐 MCP 2026-07-28。

## 三个参与方

| 角色 | 定义 | 职责 |
|------|------------|------------------|
| 宿主（Host） | 用户使用的应用进程，例如聊天助手、IDE 或批处理流水线 | 创建和管理客户端，执行安全与同意授权，聚合跨服务器上下文，协调模型 |
| 客户端（Client） | 宿主创建的对象，每条服务器连接对应一个 | 为每个请求附加协议版本和能力，隔离不同服务器的数据 |
| 服务器（Server） | 提供上下文与能力的独立程序 | 实现工具、资源、提示词与补全，声明自身能力，不查看完整对话 |

牢记一对一规则：一个客户端、一条连接、一台服务器。宿主连接五台服务器时运行五个客户端，不让一个客户端同时处理五段服务器通信。

## 本地与远程服务器

| | 本地服务器 | 远程服务器 |
|---|---|---|
| 传输 | stdio，子进程中以换行分隔的 JSON-RPC | Streamable HTTP，每条消息一个 POST，可选 SSE |
| 信任涉及的边界 | 同一机器上的进程边界 | 独立源站之间的网络边界 |
| 典型客户端数量 | 通常在进程生命周期内只有一个客户端 | 常由多个宿主实例中的多个客户端访问 |
| 凭据 | 从环境读取；stdio 实现不应运行 OAuth 流程 | 推荐使用 OAuth 2.1 流程取得的 bearer 令牌 |

## 服务器功能与客户端功能

| 功能 | 所属方 | 控制方 | 2026-07-28 中的状态 |
|---|---|---|---|
| 工具（Tools） | 服务器 | 模型 | 启用（Active） |
| 资源（Resources） | 服务器 | 应用 | 启用（Active） |
| 提示词（Prompts） | 服务器 | 用户 | 启用（Active） |
| 补全（Completion） | 服务器 | 应用，提供参数自动补全 | 启用（Active） |
| 信息征询（Elicitation） | 客户端 | 用户，通过 MRTR 往返 | 启用（Active） |
| 采样（Sampling） | 客户端 | 用户批准，客户端居间处理 | 已弃用，迁移为直接调用大语言模型服务商 API |
| Roots | 客户端 | 宿主，仅提供建议 | 已弃用，迁移为工具参数、资源 URI 或服务器配置 |

## 多服务器宿主的聚合检查清单

1. 使用 `server/discover` 独立发现每台已连接服务器，不能将一台服务器的能力假定为另一台的能力。
2. 仅对确实声明 `tools` 能力的服务器调用 `tools/list`，据此构建工具注册表。
3. 每个注册表条目和路由决策都采用宿主建立连接时自行分配的标识，例如配置键或槽位索引。不能使用 `serverInfo.name`：它由服务器自报，独立编写的两台服务器可以报告相同名称。
4. 保持工具名在单台服务器内唯一，同时预期跨服务器冲突。发生冲突时，第一个服务器的工具保留无前缀的规范名称，后续同名工具都以 `<server-id>/<tool-name>` 暴露。
5. 通过注册表条目查找调用目标，再向唯一所属连接发送 `tools/call`。无论宿主怎样聚合，接收服务器独立执行自己的错误规则：未知工具返回 `-32602`，无效参数返回工具执行错误。
6. 将每台服务器的工具、资源和提示词与其他服务器隔离。只有宿主能够看到跨服务器的信息。

## 考试要点

- 宿主为每台服务器嵌入一个客户端，一个客户端不服务两台服务器。
- 工具由模型控制，资源由应用驱动，提示词由用户控制。
- Sampling 与 roots 在 2026-07-28 中已弃用但未移除，两者仍可正常工作。
- `serverInfo.name` 用于展示和日志，不能用于身份判定或路由。
