# 审计与遥测字段参考（Audit and Telemetry Field Brief）

面向 MCPA“安全与治理”中审计目标的一页参考：让协议活动能够被追踪、归因和审阅，对齐 MCP 2026-07-28。

## traceparent 字段布局

`traceparent` 通过 `_meta` 传递，由四段以连字符分隔、小写十六进制、固定长度的内容组成；SEP-414 将其规定为反向 DNS 前缀规则的例外：

| 段 | 长度 | 含义 |
|---------|--------|---------|
| version | 2 个十六进制字符 | 格式版本，本课使用 `00` |
| trace id | 32 个十六进制字符 | 标识整个操作，各跳保持不变 |
| parent id | 16 个十六进制字符 | 标识一个跨度，每跳重新生成 |
| flags | 2 个十六进制字符 | 位标志，例如是否采样 |

全零 trace id 或 parent id 无效，必须拒绝。`tracestate`（供应商状态）和 `baggage`（用户定义上下文）是独立 `_meta` 键，随 `traceparent` 一起传播；本课服务器每跳原样转发。

## 派生子跨度

调用其他服务前，保留追踪 ID 并生成新的父跨度 ID：

```python
def child_traceparent(value):
    parsed = parse_traceparent(value)
    return make_traceparent(parsed["trace_id"], new_span_id(), sampled=parsed["flags"] != "00")
```

## 审计条目的五类字段

| 字段 | 来源 | 不应使用 |
|-------|--------|-----------|
| 谁 | 有效凭据映射到的已认证主体 | 自报、仅供展示的 `clientInfo.name` |
| 什么 | 方法、工具名及已脱敏的参数 | 原始未脱敏参数 |
| 何时 | 写入条目时取得的时间戳 | 客户端自报时间 |
| 结果通道 | 实际采用的 complete、isError 或 protocol_error | 将不同结果都压成一个通用状态 |
| 关联 | 当前跳的请求 ID 加整个操作的追踪 ID | 跨服务时只使用请求 ID |

## 脱敏规则

注册工具时指定敏感参数字段。创建条目前，将这些值替换为固定标记；替换发生在写入与哈希计算之前，避免原值进入持久记录、备份及摘要输入。工具处理器仍接收真实值，仅审计副本被脱敏。各服务器独立执行自己的日志脱敏政策。

## 哈希链验证流程

1. 从初始 genesis 值开始，将它设为预期前条哈希。
2. 顺序检查每个条目：确认 `prev_hash` 等于预期值；用保存字段重算摘要，确认等于 `hash`；随后将该条 `hash` 设为下一步预期值。
3. 干净链全部通过。直接修改内容会在该条的摘要核对处失败；若还修改了该条自身哈希，则下一条保留的 `prev_hash` 与之不符，失败点移至下一条。

这是局部篡改检测能力，不阻止底层写入。译注：能够重写整链和末尾摘要的人仍可让内部检查通过，尾部截断也需外部证据发现。可信检查点或链头必须另行保护，本例不能独立证明历史从未被重写。

## 为什么 clientInfo 不能代表主体

`clientInfo` 和 `serverInfo` 都由发送者自行填写，协议不验证其真实性，不应据此作安全决策。用 `clientInfo.name` 记录“谁”会让调用者自行选择追责日志中的身份，在写入前就破坏审计目的。

## 跨跳关联

同一操作涉及的两台服务器维护两条独立哈希链。无需共享日志，也无需让各跳请求 ID 相同。跨跳保持一致的是追踪 ID，审阅者或追踪后端按它连接记录，重建操作涉及的完整服务路径。
