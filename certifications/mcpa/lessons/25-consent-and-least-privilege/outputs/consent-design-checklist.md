# 同意授权与最小权限设计检查清单（Consent and Least Privilege Design Checklist）

面向 MCPA“安全与治理”领域的一页参考，对齐 MCP 2026-07-28。用于评审设计，不仅用于记忆。来源：`certifications/mcpa/research/mcp-2026-07-28-brief.md`，第 7、11、12 节。

## 何时询问用户

- [ ] 只读、封闭环境中的读取或报告调用，可以不弹出提示。
- [ ] 写入、删除、发送、购买或其他改变对话外部状态的调用，在运行前取得明确、知情的批准。
- [ ] 访问公共互联网或第三方系统等开放环境的调用，即使只读，也按需要批准处理；openWorldHint 默认为 true。
- [ ] 完全没有注解的工具，默认按具有破坏性、面向开放环境处理，不能默认视为安全。

## 如何收集同意

- [ ] 通过 MRTR 收集：服务器返回 `resultType: "input_required"`，`inputRequests` 中含 `elicitation/create`，通常还携带 `requestState`。
- [ ] 客户端重试使用全新 JSON-RPC id，将回答放入键名匹配的 `inputResponses`，并原样回传 `requestState`。
- [ ] 用户动作包括 `accept`（表单模式附上匹配的 `content`）、`decline` 和 `cancel`。只有有效 `accept` 构成同意；后两者都阻止执行，但表示不同事件。
- [ ] 将 `requestState` 作为攻击者可控制输入。影响执行时，保护其完整性、绑定具体调用，并只接受一次。
- [ ] 未获或被拒同意时，本课使用带 `isError: true` 的普通工具结果，不使用 JSON-RPC 错误或自创错误码。

## 如何限定同意范围

- [ ] 批准记录针对一个工具名，不针对整台服务器、类别或名称模式。
- [ ] 批准一个破坏性工具，不会授权另一工具，即使位于同一服务器且相隔片刻。
- [ ] `readOnlyHint`、`destructiveHint` 和 `openWorldHint` 只辅助决定是否提示；服务器不可信时，其注解同样不可信。执行边界由客户端实际保存的用户批准记录落实。

## 增量授权（独立的下层门禁）

- [ ] 权限范围不足时返回 HTTP `403`，通过 `WWW-Authenticate` 一次指出所有必需范围，不逐次零散索取。
- [ ] 客户端后续申请范围为已有与新要求的并集，不能用新集合替换旧集合。
- [ ] 初始申请尚无既有授权：优先使用首个挑战的 `scope`，缺失时回退参考 `scopes_supported`。
- [ ] 增量授权设置少量重试上限；超过后报告持续性授权失败，停止循环。

## 服务器列表中的最小权限

- [ ] `tools/list` 等列表可随当前请求的授权变化，但不因其他不相关请求的副作用变化。
- [ ] 根据调用方授权变化的列表，使用 `cacheScope: "private"`，不使用 `"public"`。
- [ ] 仅展示当前权限允许的工具，避免先向所有人暴露全部工具，再等其调用时拒绝。

## 设计评审中应拒绝的模式

- 一次“连接服务器”提示，悄悄覆盖该服务器现在及未来的全部工具。
- 自创“需要同意”代码，例如使用 `-32000` 至 `-32019` 旧版范围，或 `-32020` 至 `-32099` 内未定义的保留代码。
- 增量重试只申请新要求的范围，丢掉原有授权。
- 多次往返逐个索取权限，而未一次说明操作所需的完整集合。
- 不论获授权限，`tools/list` 对每个调用方展示所有工具。
- 将服务器注解本身视为执行门禁，而非提示策略的参考。
- 增量授权无限重试，没有次数上限或明确失败出口。

## 本领域考试信息

- 原参考材料称“安全与治理”占 MCPA 大纲最大比例；具体权重应与项目固定大纲对照使用。
- 课程对齐 MCP 规范 2026-07-28，无状态核心不包含 `initialize` 握手和协议会话。
- 工具有两个错误通道：请求格式错误使用 JSON-RPC 错误；希望模型读取并处理的问题，包括本例未获同意，使用 `isError: true` 结果。
