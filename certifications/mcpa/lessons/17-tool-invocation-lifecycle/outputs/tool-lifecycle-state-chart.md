# 工具调用生命周期状态表（Tool Invocation Lifecycle State Chart）

面向 MCPA“交互与执行”领域的一页参考，对齐 MCP 2026-07-28。实现客户端或服务器的生命周期与错误处理时可放在旁边参考。

## 八个检查点

| 检查点 | 报文可见性 | 决定什么 | 可能如何结束 |
|---|---|---|---|
| 发现（Discover） | 是，`server/discover`，可缓存 | 服务器提供哪些版本和能力 | 不支持客户端版本时返回 `-32022` |
| 列举（List） | 是，`tools/list`，可缓存且顺序确定 | 有哪些工具、结构定义和注解 | 返回稳定列表，没有特定工具执行结果 |
| 选择（Select） | 否 | 模型根据已有上下文选择工具 | 完全在宿主内部，不产生协议结果 |
| 确认（Confirm） | 否 | 发送调用前是否获得人工批准 | 拒绝时生命周期就此结束 |
| 调用（Call） | 是，`tools/call` | 请求真正离开客户端 | 尚无结果，只启动后续检查 |
| 校验（Validate） | 不发送新请求，决定响应路径 | 服务器是否暴露指定名称的工具 | 未知时返回协议错误 `-32602`，不再执行或产生正常结果 |
| 执行（Execute） | 不发送新请求，决定响应路径 | 参数是否符合结构定义、处理器是否成功 | 无效输入或业务失败返回 `isError` 结果；真正意外故障才使用 `-32603` |
| 结果（Result） | 是，回答 `tools/call` | `resultType` 为 `complete` 或 `input_required` | `input_required` 回到调用；`complete` 最终结束 |

## 两个错误通道

| 通道 | 结构 | 用于 | 模型能否修正 |
|---|---|---|---|
| 协议错误 | JSON-RPC `error` | 未知工具（`-32602`）、无效请求、真正的服务器故障（`-32603`） | 不能靠原样重试解决，客户端不应盲目重复 |
| 工具执行错误 | 完成结果，`isError: true` | 无效参数、上游 API 失败、业务规则违反 | 可以，这正是该通道提供可操作内容的用途 |

经验规则：本课的校验阶段失败只产生协议错误；执行阶段通常产生工具执行错误，只有调用方输入无法避免的真正内部故障才使用协议错误。

## 暂停、取消与重新发起

| 情况 | 发生什么 | 调用方如何处理 |
|---|---|---|
| `resultType: "input_required"` | 服务器需要更多输入，包含 `inputRequests`、`requestState` 或两者 | 使用新 JSON-RPC id 重试，提供键名匹配的 `inputResponses`，原样回传 `requestState` |
| 硬超时 | 不为超时本身定义新的 resultType | Streamable HTTP 关闭请求流；stdio 发送 `notifications/cancelled`，指定 `requestId`，可附原因 |
| 流中断 | 调用方丢失请求后续结果，无法恢复原流 | 用新 id 重新发起；重复有副作用调用前，将 `idempotentHint` 仅视为提示，不作为保证 |
| 取消后的迟到响应 | 已放弃的 id 仍收到结果或错误 | 忽略它 |

## 发布 tools/call 路径前检查

- 未知工具名称始终返回 `-32602`，不能使用 `-32601`。
- 工具参数结构校验失败和业务规则失败返回 `isError: true`，不包装为 JSON-RPC 错误。
- 每个请求，包括重试，都在 `_meta` 中携带协议版本和客户端能力。
- `input_required` 之后的每次重试都使用新 id，并逐字节回传 `requestState`。
- 流中断后的每次重新发起都使用新 id；有副作用工具通过显式不透明句柄引用状态，避免靠猜测重复操作。
- 超时必须有硬上限，即使进度通知持续到达也不能无限延长。
- stdio 取消使用通知，不是期待回复的普通请求。
