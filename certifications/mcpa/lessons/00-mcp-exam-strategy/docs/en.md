# MCPA 考试大纲应指导学习预算，而非充当勾选清单

> 教学目录列出考试可能涉及什么；考试大纲（Blueprint）则说明各部分出现的频率。应将 MCPA 大纲作为学习时间的分配依据，避免把它当成浏览一遍就抛开的目录。

**Type:** Orientation
**Languages:** Python
**Prerequisites:** None
**Time:** ~45 minutes

## 学习目标（Learning Objectives）

- 列出 MCPA 的五个领域及其准确的公开权重，并确认合计为 100%。
- 将领域的大纲权重换算为固定学习时间预算中的相应份额。
- 说明考试形式、费用、认证有效期和补考政策，并处理认证页面的 90 分钟时长与发布新闻稿中 120 分钟这一冲突。
- 说明考试题数和及格分数尚未公布，以及这对考生判断准备程度的影响。
- 识别题目中基于旧版协议的干扰项，例如 `initialize` 握手、会话、用 `-32601` 表示未知工具，并推导 2026-07-28 版本的对应做法。
- 沿着从本导论到综合实践的 34 课路线，指出每课所属的一个或多个领域。

## 问题（The Problem）

模型上下文协议涉及许多内容：角色与消息、模式、传输、工具和资源的生命周期、采样、错误处理、OAuth、同意、可审计性，以及围绕协议形成的生态。考生打开 MCPA 指南，从头到尾阅读，并给每个主题分配大致相同的时间，其实已经在不知不觉中作出一个学习规划决策：假定各部分同等重要。实际权重并不相同。定义考试的认证页面还发布了考试大纲，将内容划分为五个领域，并为每个领域指定百分比。这个数字有实际意义：它说明考试内容平均如何分布，是考试提供方在考前给出的最有价值的备考线索之一。

忽略大纲相当于规划中存在缺陷，就像构建了一个从不失效的缓存：表面上没有问题，直到假设与现实的偏差造成损失。平均分配时间必然会让你对占考试 26% 的领域投入不足，对仅占 14% 的领域投入过多。这种偏差还会累积，因为“交互与执行”和“安全与治理”合计占据一半权重。不了解这一点的计划，会把权重接近另一领域两倍的内容当成可以等量对待的部分。

第三个问题损失的是分数。MCPA 题目依据 2026-07-28 版本编写，但考生对 MCP 的直觉往往来自旧教程、博客，甚至本课程修订前的草稿；这些资料描述的协议会先执行 `initialize` 握手，并通过会话保存状态。描述旧协议的选项读起来熟悉，甚至显得权威，而熟悉感恰恰使它成为有迷惑性的错误答案。不能迅速区分旧版认知与 2026-07-28 事实的考生，会因错误的理由觉得选项正确。此外，34 节课很容易一路读完，却始终不知道每课训练的是哪个领域。本课将在你继续学习前处理这四个问题：将公开权重转化为明确的时间预算；根据指南已公布和未公布的信息建立诚实的准备度指标；训练识别旧版干扰项的反应；提供把全部 34 课映射到五个领域的路线。

## 概念（The Concept）

先看构成计划基础的数字。MCPA 大纲公布了五个领域：MCP 基础（MCP Fundamentals）16%，架构与组件（Architecture and Components）14%，交互与执行（Interactions and Execution）26%，安全与治理（Security and Governance）24%，用例与生态（Use Cases and Ecosystem）20%。合计恰好为 100%，值得亲自核算；如果总和不对，可能存在转录错误。各领域还公布了具体子能力。MCP 基础包括目的与范围、核心概念、互操作性与价值。架构与组件包括模式与结构化数据，宿主、客户端、服务器角色，以及模型交互流程。权重最高的交互与执行包括交互模式与响应处理、错误处理、工具调用生命周期和协议原语。安全与治理包括信任边界、权限与同意、风险与安全控制、可审计性与可观测性。用例与生态包括角色与采用、实际运行用例及生态可移植性。本段信息及其来源和检索日期均记录在仓库的 `certifications/mcpa/research/source-verification-ledger.md` 中，便于自行核查。

再看考试安排。考试采用在线监考和选择题形式，内容对齐 Model Context Protocol 2026-07-28 规范，也是本课程的目标版本。仅考试费用为 250 美元，与捆绑订阅分开计算。认证有效期为两年，首次未通过的考生包含一次补考机会。时长存在来源冲突：认证页面写 90 分钟，而 Linux Foundation 自己的发布新闻稿写 120 分钟。本课程采用更直接面向该考试的认证页面，并将新闻稿数字记为尚未解决的差异，避免静默选择一个更方便的数字；`certifications/mcpa/research/source-verification-ledger.md` 保留两个数字及各自来源，使用前可以重新核查。两份来源都没有给出准确题数和及格分数。应承认这些信息尚未公布，避免用猜测填补。这意味着准备度目标不能是“60 题中至少答对 N 题”，而应是“五个领域均达到扎实、分布合理的掌握程度”，因为公开资料只支持后者。

接下来将数字转化为计划。某领域占考试内容的百分比，也可以作为学习时间预算中有依据的份额：领域时间等于总预算乘以该领域权重，再除以 100。这是普通的比例分配，和预算科目或资产份额的计算相同，且具有确定性：预算和大纲相同，分配就相同。计划的另一半是衡量现状。直接平均五个领域的练习准确率，会将 14% 的领域与 26% 的领域等量对待，使低权重领域的优势掩盖高权重领域的薄弱。加权准备度先将各领域准确率乘以其大纲权重，再求和，让指标反映考试自身的重点。这两项计算，时间分配与加权准备度，均以小型确定性函数实现在 `code/main.py` 中；下图将五个权重可视化，供你对照自己的分配。

### 阅读题目：识别旧版协议干扰项

好的干扰项并非随机噪声。MCPA 对齐 2026-07-28，但 MCP 已经历五个修订版；首个 2024-11-05 版本的认知仍广泛存在于旧博客、缓存文档，以及本课程修正前的草稿中。这些说法流畅而自信，因此尤其容易误导。与其笼统提醒自己谨慎，不如建立具体检查习惯。首先，留意任何描述首次实际请求前需要配置步骤、握手或协商的选项；2026-07-28 没有这些前置步骤，每个请求通过 `_meta` 自带协议版本和能力，因此 `initialize` 调用或“连接开始时先协商版本”的说法暴露了旧版背景。其次，留意通过会话或粘性连接解释服务器如何跨调用记忆状态的选项；2026-07-28 是无状态协议，跨请求状态使用服务器生成的显式句柄，以普通参数传回，不依赖隐式会话。第三，核对错误码的实际含义：未知工具使用 `-32602`；看似熟悉的 `-32601` 专用于未知方法。工具参数不符合模式时，返回的是带 `isError: true` 的普通结果，供模型读取和修正，不属于协议错误。`certifications/mcpa/research/mcp-2026-07-28-brief.md` 第 16 节持续记录这些陷阱，将旧认知与替代它的 2026-07-28 事实配对；开始第一组练习前和考前一晚都应重读。

### 学习路线：五个领域中的 34 节课

本路线共 34 课，编号 00 至 33，每课至少关联一个领域。多数课程只属于一个领域，例如工具原语属于交互与执行，OAuth 属于安全与治理。少数课程确实跨越两个领域：JSON-RPC 与元数据同时关联基础和架构，因为消息封装既是核心概念，也是考试单独考查的架构组成；传输与 HTTP 请求头同样跨越交互和架构，同一机制可以从两个角度出题。最后的第 33 课综合实践有意关联全部五个领域，因为它要求在一份交互记录中运用各领域的知识。本课 `code/main.py` 将完整路线编码为数据，因此脚本或学习者可以精确查询“哪些课程训练安全与治理”，而不必凭记忆猜测。

## 交互实验（Interactive Lab）

运行下方脚本。它会校验领域权重和 34 课路线，按两份官方来源打印考试信息，包括 90 与 120 分钟的冲突，以及因来源均未公布而有意设为 `null` 的两个字段。随后将 40 小时示例预算分配给五个领域，并打印基于示例练习分数的准备度，同时给出同一组分数的普通平均值，便于观察差异。最后打印路线总长度，以及 `route_for_domain` 针对两个示例领域返回的课程标识。

```bash
python3 code/main.py
```

将打印的分配表与图示对照。最高的两组柱，交互与执行、安全与治理，也应对应最大的时间分配，因为两者使用相同权重。修改 `demo()` 中传给 `allocate_study_hours` 的 `total_hours` 再运行，各领域小时数会一起变化，但比例保持不变，因为分配依据大纲而非某个固定预算。在课程目录的 Python 交互环境中尝试调用 `main.route_for_domain("not-a-real-domain")`，观察它拒绝请求，而非静默返回空路线。

## 实践实验（Practice Lab）

进入下一课前，用自己的数字完成三件事。首先，确定从现在到考试日期实际可投入的小时数，调用 `allocate_study_hours`，将五个领域的目标写在之后能反复看到的位置，例如下方交付的速查表。其次，做练习或诊断测评时，持续为每个领域记录 `(correct, total)`，定期调用 `estimate_readiness`。观察开始练习一个此前未作答领域后指标的变化：未练习领域在估计中计零分，不会被悄悄排除。第三，对准备度显示最薄弱的领域调用 `route_for_domain`，按返回顺序学习这些具体课程，避免只是习惯性沿编号前进。每周重复检查。一份只制定一次、从不回顾的计划，只能代表当时的快照。

## 验证结果（Verify It）

运行 `python3 -m unittest discover code/tests`。测试检查：五个权重合计恰好为 100，并拒绝不符合的权重集合；预算按准确比例分配，分配总和等于原预算；加权准备度对高权重领域的掌握给予更多贡献；零小时预算在每个领域均得到零；未作答领域计零分而不产生除零错误；准备度估计和路线查询都拒绝未知领域；路线覆盖 00 至 33 的全部 34 课，且只有综合实践跨越全部领域。任何失败都说明代码与课程发生偏离；算术行为以代码为准。

## 与综合实践的联系（Capstone Connection）

`estimate_readiness` 并非一次性演示。第 33 课准备度综合评审会要求再次运行同一加权评分模型，此时使用你真实的诊断或模拟考试领域成绩，判断是否适合预约考试，还是仍需重学某个领域。保留速查表、两个学习函数和路线表。整条 34 课路线的每一课都归入这里定义的至少一个领域；综合实践要求将自己的数字代回同一套计算，证明覆盖程度符合大纲，而不只是证明按顺序读完了课程。

## 关键术语（Key Terms）

| 术语 | 含义 |
|------|------|
| 考试大纲（Blueprint） | 公布五个 MCPA 领域及其百分比权重的表格 |
| 领域权重（Domain weight） | 某领域平均占考试内容的百分比 |
| 学习时间预算（Study-hours budget） | 考前可用的固定小时数，按权重分配到领域 |
| 准备度估计（Readiness estimate） | 使用大纲权重计算各领域练习准确率的加权平均值 |
| 未公布信息（Unpublished fact） | 两个官方来源均未说明的考试细节，例如题数或及格分数 |
| 旧版协议干扰项（Legacy-era distractor） | 描述 2026-07-28 之前 MCP 行为的错误选项，例如 `initialize` 握手或会话 |
| 学习路线（Route） | 34 节课分别对应所训练领域的映射 |
