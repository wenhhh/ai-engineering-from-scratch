# 无状态设计检查清单（Stateless Design Checklist）

面向 MCPA“MCP 基础”领域的一页检查清单，对齐 MCP 2026-07-28。

## 不变条件

每个请求都携带服务器作答所需的全部信息。服务器不得根据任何先前请求推断能力、协议版本或身份，即使那些请求来自同一连接。

## 无状态性的运维价值

- 任意副本都能回答任意请求：无须粘性会话，也无须同步逐实例的协议记忆。
- 连接中断后可以向其他副本重试，因为原副本没有保存需要继承的协议状态。
- 负载均衡器按普通规则路由，无须会话亲和性。

## 连接与会话

| 问题 | 回答 |
|---|---|
| 打开的 stdio 进程或 HTTP 连接是否构成会话？ | 否。客户端可以在同一传输通道上交错发送不相关请求。 |
| tools/list、resources/list 或 prompts/list 能否因连接不同而变化？ | 不能。 |
| 这些列表能否随当前请求所呈现的授权变化？ | 可以，授权属于每请求输入，不是连接状态。 |
| 服务器能否通过先前调用的副作用改变工具列表？ | 不能。应始终暴露该工具，改用句柄参数设门禁。 |

## 使用服务器生成句柄设计有状态工具（SEP-2567）

1. 暴露创建工具（例如 create_basket），通过 structuredContent 返回不透明句柄。
2. 任何操作该状态的工具，都将句柄作为普通参数接收。
3. 每次调用都针对句柄检查调用方授权；句柄用于命名状态，本身不授予访问能力。
4. 在创建工具描述中说明句柄存续时间，让模型创建状态前了解策略。
5. 句柄过期、未知或归他人所有时，返回工具执行错误（isError: true）并指出相关句柄，让模型通过重新创建状态恢复。

## 发布前检查

- [ ] 每个请求处理器都从 params._meta 读取 protocolVersion 与 clientCapabilities，不从同一连接的先前请求读取。
- [ ] 授权相同时，tools/list、resources/list 和 prompts/list 的结果不受发起连接影响。
- [ ] 工具调用不会改变后续列表查询的结果；有条件使用的工具始终暴露，并通过句柄参数设门禁。
- [ ] 跨调用状态由服务器生成的不透明显式句柄引用，句柄作为普通参数传回，不从连接身份推断。
- [ ] 创建工具文档说明了句柄的授权、不透明性和存续时间策略。
- [ ] 过期、未知或属于其他主体的句柄，返回带解释的 isError: true，不返回 JSON-RPC 错误。
- [ ] 服务器从不使用 clientInfo、serverInfo 或其他自报字段作出授权决策。
- [ ] 同一已认证主体的两条连接，例如编排器及其子智能体，看到相同列表结果并可共享缓存。

## 2026-07-28 移除的机制

- initialize 请求与 notifications/initialized：不再存在开场握手。
- Mcp-Session-Id 请求头与协议级会话。
- 连接级能力范围：能力如今通过 _meta 在每个请求中传递。

## 考试要点

- 无状态是协议默认行为，无须显式选择某种特殊模式。
- 句柄只是工具结果和工具参数中的普通字符串；协议没有定义专用句柄类型或报文格式。
- 旧资料中的会话描述对应已移除概念，不能直接当作当前行为。
