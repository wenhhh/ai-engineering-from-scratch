# 缓存与分页决策指南（Caching and Pagination Decision Guide）

正确实现 MCP 客户端与服务器的一页参考，对齐 MCP 2026-07-28。

## 这个结果是否需要 ttlMs 与 cacheScope？

只有六种操作可缓存，而且仅限 `resultType` 为 `"complete"`：

| 操作 | 典型 cacheScope | 说明 |
|-----------|--------------------|-------|
| `server/discover` | public | 各调用方看到相同服务器说明 |
| `tools/list` | 通常 public | 仅工具集随调用方变化时使用 private |
| `prompts/list` | 通常 public | 与 tools/list 相同 |
| `resources/list` | public 或 private | 列表按调用方过滤时使用 private |
| `resources/templates/list` | public | 模板通常不随调用方变化 |
| `resources/read` | 依资源而定 | 用户专属内容使用 private |

`input_required` 不可缓存，也不携带这两个字段。MRTR 重试产生的结果即使仍须报告两个字段，也不能存入缓存。

## 选择 ttlMs

- 很少变化的数据使用较长 TTL，如静态参考资料或稳定工具目录。
- 变化频繁或过期代价高的数据使用较短 TTL，如实时队列深度或余额。
- 必须始终视为过期时使用 `0`，例如服务器无法通过通知撤销其缓存有效性的资源。
- 服务器不发送负值；客户端收到负值则归为 `0`。
- 旧服务器缺少 `ttlMs` 时也按 `0`，不能假定较长默认值。

## 选择 cacheScope

- `"public"`：字节不包含调用方专属内容，客户端、网关或代理可存储并提供给其他调用方。
- `"private"`：字节取决于调用方，只有相同授权上下文可以复用。
- `cacheScope` 只指导缓存，不执行访问控制。服务器仍逐请求授权，客户端仍正常认证每次调用；范围字段仅决定缓存能否共享已经取得的内容。

## 客户端缓存检查清单

- 缓存键包含请求方法及影响结果的参数，例如 `resources/read` 的 `uri` 和分页查询的 `cursor`。
- 私人条目按授权上下文隔离，不能用一枚令牌存入的私人缓存回答另一枚令牌的查询。
- 不存储 `input_required` 结果。
- 不存储 MRTR 重试后的完成结果。
- 收到相关 `list_changed` 通知时立即使受影响条目失效，即使 TTL 尚未结束。
- 不把 TTL 当作持续后台轮询定时器，在下次需要数据时惰性检查。
- 重新获取因网络错误或服务器不可用而失败时，可以按适用策略返回旧副本，避免直接令调用方失败。

## 分页检查清单

- 将 `cursor` 视为不透明字符串，不解析、不解码、不推断内部位置。
- 不假定页大小固定，服务器可在不同页之间调整。
- 只要存在 `nextCursor` 就继续，包括值为 `""`；只有缺少 `nextCursor` 才表示结束。
- 未知游标返回 `-32602 Invalid params`。收到后丢弃相应列表的缓存页，需要完整列表时从头开始。
- 不保证跨页一致性。原文建议需要完整重新读取时不带游标从头获取；译注：重新遍历本身不建立原子快照保证。
- 同一次列表遍历的每一页必须采用相同 `cacheScope`。

## 考试要点

- `ttlMs` 是新鲜度提示，不保证底层数据从未改变。
- 空字符串游标合法，不代表列表结束。
- MRTR 重试结果不能缓存，即使规范仍要求其中包含 ttlMs 与 cacheScope。
- 确定性顺序同时帮助客户端缓存，以及大语言模型服务商复用逐字节相同前缀的提示缓存。
