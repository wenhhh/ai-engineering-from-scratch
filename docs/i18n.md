# 国际化（Internationalization，i18n）

> 分支说明：本文记录上游原有的机器翻译流程，供维护和对照使用，不是当前中文分支的交付方案。本分支直接翻译原路径下的内容，不使用旧翻译分支，也不在缺失时回退英文；认证课程同样纳入翻译范围。当前约定见 [TRANSLATION.md](../TRANSLATION.md)。下文的成本、时长和质量描述均为上游原文记录，未作当前服务价格核实。

英文课程是权威源版本。翻译后的**课程** Markdown 由机器生成，**从不提交到 `main`**，而是存放在独立的 `translations` 分支。站点在运行时通过与英文相同的免费渠道（`raw.githubusercontent.com`）获取译文。不使用 Vercel 函数或键值存储（KV），没有按访问次数产生的费用。唯一例外是各语言的 **README**：为保证质量，由人工编写并提交到 `main`，详见下文。

该流水线只覆盖 `phases/` 下的课程。认证课程仍仅提供英文，并明确排除在机器翻译和电子书生成范围之外。

默认引擎是 **NLLB-200**（[No Language Left Behind，Meta AI，2022](https://arxiv.org/abs/2207.04672)），这是覆盖 200 种语言的开放翻译模型，**在 GitHub Actions 运行器（Runner）内执行，不需要 API 密钥，也不产生账单**。计算资源来自免费的持续集成（CI）运行器，没有翻译 API 费用。付费大语言模型（LLM）服务商 Anthropic / OpenAI 和 DeepL 仍可通过 `--provider` 选用，作为提高翻译质量的升级方案。

## 组成部分（Pieces）

`languages.json` 注册表驱动机器翻译相关功能，包括课程、站点语言切换器和电子书构建矩阵。各语言的 **README 独立管理**：语言集合与翻译区块存放在 `scripts/readme_translations.py` 中，为保证质量由人工编写，不依赖该注册表。

| 组成部分 | 位置 | 是否提交到 main |
|-------|-------|--------------------|
| 语言注册表 | `languages.json` | 是，一个小文件 |
| 课程翻译脚本 | `scripts/translate_lessons.py`，仅遍历正文 | 是 |
| README 生成器及译文 | `scripts/build_readme_i18n.py` + `scripts/readme_translations.py`，人工编写 | 是 |
| CI 工作流 | `.github/workflows/translate.yml`，按语言与阶段分片 | 是 |
| 翻译后的课程 Markdown | `translations` 分支中的 `i18n/<lang>/…/<lang>.md` | 否，存放在独立分支 |
| 翻译后的 README | `i18n/<lang>/README.md`，从 `README.md` 页首链接访问 | **是** |
| 翻译后的电子书 | `scripts/build_book.py --lang <code>` 读取译文 Markdown，生成 `aiefs-vol{n}-{slug}-<lang>.epub/.pdf` 发布附件；单课缺译时回退英文 | 否，作为发布附件 |
| 语言切换选项 | `site/langs.js`，由 `build.js` 根据 `source` / `ci:true` 集合生成 | 否，与 `data.js` 一样由 gitignore 排除 |
| 站点语言切换器 | `site/lesson.html` | 是，包括界面与获取逻辑 |

## 添加语言（Add a language）

在作为唯一事实来源的 `languages.json` 中添加一条记录。字段如下：

- `code`：用于文件名、URL 和语言切换器取值的语言标签。
- `name`：英文名称，用于 LLM 服务商的提示词。
- `native`：语言切换器中显示的名称。
- `nllb`：FLORES-200 代码，例如 `zho_Hans`、`tur_Latn`；默认 NLLB 服务商**必须**提供此字段。请求的语言缺少该值时，`translate_lessons.py` 会退出。
- `ci`：设为 `true`，将该语言纳入推送自动触发的工作流构建矩阵。`workflow_dispatch` 不受此限制，可请求任意已注册语言。

两个矩阵都读取 `ci: true`，因此同一标志同时决定是否参与课程翻译及站点语言切换。`build.js` 只将 `source` / `ci:true` 对应的语言写入 `site/langs.js`，避免切换器提供站点无法供应的语言。README 语言栏独立管理，可以列出 `readme_translations.py` 覆盖的任意语言，无需修改其他位置。

## 运行流程（How it runs）

1. 向 `main` 推送时，若修改了 `phases/**/docs/en.md`、`languages.json` 或翻译工作流本身，就会触发 `.github/workflows/translate.yml`。认证课程的改动不会触发它。
2. 矩阵按**每个“语言、阶段”组合一个任务（Job）**划分。在 CPU 运行器上完整翻译一门语言的 523 课约需 27 小时，超过 6 小时的任务上限，因此早期按语言划分的任务总是在发布前超时。按阶段拆分后，最大的任务，即阶段 19 的 85 课，约需 4.5 小时，低于上限。每个任务从分支恢复该语言之前的输出，运行 `translate_lessons.py --phase <phase>`，然后通过拉取并重试的循环，只推送自己负责的 `i18n/<lang>/phases/<phase>/` 分片，使互不重叠的分片能够无冲突合并。
3. 站点语言切换器设置 `?lang=<code>`；`fetchLesson` 获取 `…/translations/i18n/<lang>/…/<lang>.md`，若译文尚未发布，则**回退到权威英文原文**。英文模式（`lang=en`）的获取路径与引入国际化之前逐字节相同。

## 复用已有翻译（Never wastes a run）

每节课程以英文源文件的 `sha256` 为缓存键，保存在按“语言、阶段”划分的缓存中（`i18n/<lang>/.cache/<phase>.json`）。运行器逐课写入缓存，并在**任务结束时发布到 `translations` 分支**。因此：

- 首次运行翻译全部内容。此后每次成功完成的运行都**只**重新翻译英文发生变化的课程，其他课程命中缓存后立即跳过。
- 被取消或中断的阶段任务不会发布，因此会丢失该任务在运行器本地的进度。下次运行从该阶段**最近一次已发布**的缓存恢复。每个分片只处理一个阶段，能够在任务时限内完成并发布。

## 各语言 README（Per-language README）

README 是项目入口页面，因此其译文采用**人工编写**方式保证质量，而不是机器生成，并存放在 `main` 的 `i18n/<lang>/README.md` 中。`scripts/readme_translations.py` 以精确匹配的英文区块为键保存译文；`scripts/build_readme_i18n.py` 在英文 README 副本中**只替换**已翻译的行区间，从而重建各语言文件。其余内容，包括横幅、徽章、523 行课程表、全部代码及链接*文字*，均原样保留，每次运行都会通过往返一致性检查进行断言。唯一主动转换的是链接和图片的*目标路径*：相对于仓库根目录的路径加上 `../../` 前缀，使其在两级子目录下仍能解析。围栏代码块会跳过，因此看似链接的代码不会改动。未提供译文的区块回退到英文，便于逐种语言扩大覆盖范围。

`python3 scripts/build_readme_i18n.py --check` 在 CI（`curriculum.yml`）中执行；若已提交的 README 过期，检查就会失败。README 数量统计机器人在同步英文统计区块时，也会重新生成这些文件。

## 翻译时保护的内容（What is protected during translation）

NLLB 是句子翻译模型，不是指令遵循模型，因此遍历器只将正文交给它。课程按行处理：围栏代码块、表格、图片行和元数据头（`**Type:** … **Time:**`）原样透传；其他行中的行内代码 `` `code` ``、`$math$`、图片引用、完整 Markdown 链接、`**bold**` 术语和 URL 都先替换为占位符（Placeholder），仅翻译其间的纯文本，再恢复原内容。粗体片段予以保留，是因为在本课程中它们几乎都是需要保留英文的技术术语，例如跳字模型（Skip-gram）和负采样（Negative sampling）。

这一点通过机械检查验证：使用不改变文本的恒等“翻译”运行遍历器，可以**逐字节还原全部 523 课**，因此实际运行只可能改动正文。若占位符无法完整往返恢复，该课程就保留英文，作为故障保护（Fail-safe）。

## 成本（Cost）

默认服务商 `nllb`：**免费。** NLLB-200 在 GitHub Actions 运行器中执行，不需要 API 密钥或密钥配置，也不按词元（Token）计费。唯一消耗的是免费的 CI 计算资源；模型在运行之间缓存，只对变化的课程重新翻译，使用 sha256 缓存判断。Vercel 成本不变。

可选升级（`--provider anthropic|openai|deepl`）能改善流畅度，原文估算每种语言完整翻译一遍的费用为数十美元以内，可用于以后润色访问量较高的语言。这些服务商从 `LLM_API_KEY` 环境变量读取密钥，DeepL 也使用同一变量。NLLB 仍是默认的零费用方案。

## 质量示例（Quality sample）

下方展示 `05 · 03 Word Embeddings` 翻译到步骤 1 的示例：正文自然可读，而代码、公式、`king - man + woman`、技术术语和元数据头保持不变。原文将其描述为 LLM 级流畅度，也就是 `--provider anthropic` 的产出水平；免费的默认 NLLB-200 方案措辞稍朴素，但同样遵守内容保护保证。以后可将高访问量语言升级到 LLM 服务商，以获得同类润色效果。以下原始语言示例保留原貌，便于对照。

### 简体中文 (zh)

> # 词嵌入 —— 从零实现 Word2Vec
>
> > 词以其所处的语境为意。用一个浅层网络训练这个想法,几何结构便会自然浮现。
>
> **Type:** Build · **Languages:** Python · **Prerequisites:** 阶段 5 · 02(BoW + TF-IDF)、阶段 3 · 03(从零实现反向传播) · **Time:** 约 75 分钟
>
> **问题** —— TF-IDF 知道 `dog` 和 `puppy` 是不同的词,但不知道二者含义几乎相同。在 `dog` 上训练的分类器无法泛化到讨论 `puppy` 的评论。你可以靠列举同义词勉强弥补,但这在罕见词、领域术语,以及所有你未曾预料的语言上都会失效。
>
> 你想要的是这样一种表示:`dog` 和 `puppy` 在空间中彼此靠近;`king - man + woman` 落在 `queen` 附近;在 `dog` 上训练的模型能免费地把部分信号迁移到 `puppy`。
>
> **核心概念** —— **分布假说**(Firth,1957):"要了解一个词,就看它与哪些词为伴。" Word2Vec 有两种形式:**Skip-gram** 给定中心词预测周围词(窗口为 2 时 `cat -> (the, sat, on)`);**CBOW(连续词袋)** 给定周围词预测中心词。网络只有一个隐藏层且无非线性:输入是词表上的 one-hot 向量,输出是 softmax,训练后丢弃输出层,隐藏层权重即为嵌入。诀窍是用**负采样(negative sampling)**把对 10 万词的 softmax 转成二分类。

### 土耳其语（Türkçe，tr）

> # Kelime Gömmeleri —— Word2Vec'i Sıfırdan
>
> > Bir kelime, birlikte bulunduğu kelimelerden ibarettir. Bu fikri sığ bir ağ ile eğitin, geometri kendiliğinden ortaya çıkar.
>
> **Type:** Build · **Languages:** Python · **Prerequisites:** Aşama 5 · 02 (BoW + TF-IDF), Aşama 3 · 03 (Sıfırdan Geri Yayılım) · **Time:** ~75 dakika
>
> **Problem** —— TF-IDF, `dog` ve `puppy`'nin farklı kelimeler olduğunu bilir ama neredeyse aynı anlama geldiklerini bilmez. `dog` üzerinde eğitilen bir sınıflandırıcı, `puppy` hakkındaki bir yoruma genelleme yapamaz. Eş anlamlıları listeleyerek geçiştirebilirsiniz, ama bu; nadir terimlerde, alana özgü jargonda ve öngöremediğiniz her dilde başarısız olur.
>
> `dog` ve `puppy`'nin uzayda birbirine yakın düştüğü, `king - man + woman`'ın `queen`'e yakın indiği bir temsil istiyorsunuz. Word2Vec bunu verdi: iki katmanlı bir ağ, trilyon token'lık eğitim, 2013'te yayımlandı.
>
> **Kavram** —— **Dağılımsal hipotez** (Firth, 1957): "Bir kelimeyi birlikte bulunduğu kelimelerden tanırsın." İki tür: **Skip-gram** merkez kelimeden çevredekileri tahmin eder (pencere 2 ile `cat -> (the, sat, on)`); **CBOW** çevredekilerden merkezi tahmin eder. Ağın doğrusal olmayan aktivasyonu olmayan tek bir gizli katmanı vardır: girdi one-hot vektör, çıktı softmax'tır; eğitimden sonra çıktı katmanı atılır, gizli katman ağırlıkları gömmelerdir. Püf nokta, 100 bin kelimelik softmax'ı **negatif örnekleme (negative sampling)** ile ikili sınıflandırmaya çevirmektir.


注意，两种语言中的 `dog`、`puppy`、`king - man + woman`、`softmax`、`one-hot`、`Skip-gram`、`CBOW`、`TF-IDF`、`Word2Vec` 以及 `**Type:** / **Time:**` 标签均保持原样，周围正文则完成本地化（Localization）。这些保护由占位符往返检查机械执行，而非交由模型自行决定。
